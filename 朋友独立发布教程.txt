# 用自己的小程序账号发布班级积分站

给第一次在自己电脑上部署这份源码的朋友

适用源码：班级积分站优化版 · 编写日期：2026 年 10 月 12 日

这份教程只讲你的情况：**拿到朋友的源码，在你自己的电脑上，用你自己的微信小程序账号，创建你自己的云数据，最后发布给别人使用。**按顺序操作，不需要另外搭建网站服务器，也不需要先学会写程序。

完成后，小程序归你的账号管理，学生、积分、规则保存在你的云环境中。电脑主要用于开发和发布，老师和学生最终在手机微信中使用；电脑关闭后，已经发布的小程序和正常运行的云资源仍可提供服务。

## 00 先看完整路线

| 顺序 | 要完成的事 | 完成后得到什么 |
| --- | --- | --- |
| 1 | 准备自己的小程序账号 | 你的 AppID 和可登录的开发者微信 |
| 2 | 解压源码，先替换原项目连接配置 | 一份准备独立部署的本地项目 |
| 3 | 导入微信开发者工具，开通自己的云环境 | 你的云环境 ID |
| 4 | 建集合、班级文档和学期 | 你的 CLASS_ID、当前学期数据 |
| 5 | 部署 whoami 和 score | 可识别用户、执行管理操作的云函数 |
| 6 | 将你的 openid 配置为管理员 | 小程序中出现“管理员”和“记一笔” |
| 7 | 测试记分，再导入自己的学生名单 | 经核对的班级数据 |
| 8 | 上传代码，选体验版，手机测试 | 可给指定体验成员扫码的入口 |
| 9 | 按平台要求提交审核并发布 | 可按平台规则访问的正式小程序 |

**你需要换的是 AppID、云环境 ID、班级 ID，并重新获取自己的 openid。**只修改学校或班级名称，不能完成独立部署。

本教程附的源码保持现有优化版字节不变，里面仍有原项目连接配置。请先做第 03 节的替换，再导入运行。原账号、原云环境、原班级数据不需要交给你，你也不用让朋友把你加进原项目。

常用官方入口：

## 02 找到你自己的 AppID

### 已有小程序账号

1. 浏览器打开微信公众平台，用你的小程序管理账号登录。
2. 先核对登录的是“小程序”，不是公众号；如果名下有多个小程序，选这次要发布的那个。
3. 在“开发管理 → 开发设置”或同类账号信息页面找到 **AppID（小程序 ID）**。
4. 复制完整值，记到包内 `配置记录表.txt` 的 AppID 项。它通常是 `wx` 开头的一串字符。
5. 在“管理 → 成员管理”检查你用于开发者工具登录的微信是否有开发权限。自己是管理员时通常可直接使用；由别人管理的账号需管理员添加你。

### 还没有小程序账号

1. 在微信公众平台点“立即注册”，选择“小程序”。
2. 按平台引导完成邮箱、主体和管理员信息；选择与你真实情况相符的主体类型。
3. 注册完成后登录，找到 AppID，再检查云开发能否开通、所选服务类目能否用于你的账号主体。
4. 若某项需要认证、资质或备案，按平台实际提示处理；未完成时可先准备本地源码，但不要把本地编译成功当作已经能正式发布。

**AppID 和 AppSecret 是两种东西。**本项目常规配置不需要把 AppSecret 写进源码，不需要把账号密码或密钥发给朋友。测试号、游客模式不能替代完整的自有账号云开发与发布流程。

**这一阶段的成功标志：**你有一个真实 AppID，并能使用有开发权限的微信登录工具。

## 03 解压源码，先移除原项目连接

1. 把压缩包保存到电脑。右键 → “全部解压”，不要直接在 ZIP 窗口里修改文件。
2. 放到固定目录，例如 `D:\miniapp\班级积分站_朋友独立发布包`；没有 D 盘可以放到“文档”中。
3. 专用交付包解压后有以下结构：

```text
班级积分站_朋友独立发布包/
├─ 00_从这里开始.txt
├─ 朋友独立发布教程.html
├─ 朋友独立发布教程.md
├─ 配置记录表.txt
├─ 发布前验收清单.txt
├─ templates/
│  ├─ classConfig.example.json
│  ├─ terms.example.json
│  └─ 名单示例.txt
└─ class-score-miniapp/
   ├─ app.js
   ├─ app.json
   ├─ project.config.json
   ├─ pages/
   ├─ services/
   ├─ assets/
   └─ cloudfunctions/
      ├─ whoami/
      └─ score/
```

4. 进入 `class-score-miniapp`，用记事本或代码编辑器打开 `project.config.json`。找到 `"appid"`，只把值换成你第 02 节取得的 AppID。例如：

```json
"appid": "替换为你自己的真实AppID"
```

上面只是一行示意，不要用这一行覆盖整个 JSON 文件；保留它原有的其他字段、英文双引号和逗号。保存后文件名仍应是 `project.config.json`，不能变成 `.json.txt`。

5. 打开同目录 `app.js`。找到顶部两行，先换成下面的待配置值并保存：

```js
const CLOUD_ENV_ID = 'YOUR_CLOUD_ENV_ID'
const CLASS_ID = 'YOUR_CLASS_CONFIG_DOC_ID'
```

这些以 `YOUR_` 开头的值是源码能够识别的占位配置。这样在你还没创建自己的数据前，程序会显示待配置提示，不会正常连接原班级。后面第 05、07 节再分别填入真实值。

6. 在文件中确认你没有继续使用原配置：

| 原配置，仅用于查找替换 | 应改成 |
| --- | --- |
| `wx1cd9863da1e51baa` | 你的 AppID |
| `cloudbase-d9gxek4i448d8dae8` | 暂用 `YOUR_CLOUD_ENV_ID`，稍后填你的环境 ID |
| `2612439e6a9a118801d171b720b78eef` | 暂用 `YOUR_CLASS_CONFIG_DOC_ID`，稍后填你的班级文档 `_id` |

如果你拿到的是旧包，目录名可能不同。判断项目根目录的方法只有一个：**这一层直接包含 `app.json`、`app.js` 和 `project.config.json`。**原包可能带原班名单或旧迁移说明；本次独立部署应使用自己的名单，不按“继续原环境”的步骤操作。

**成功标志：**`project.config.json` 已是你的 AppID，`app.js` 已改成两项占位值。此时还不能正常读云数据，属于正常阶段。

## 04 安装工具并导入

1. 在微信官方下载页选择适合电脑系统的稳定版开发者工具，安装并打开。
2. 用第 02 节有开发权限的微信扫码登录。
3. 在首页选择“小程序 → 导入项目”。
4. 项目目录选择解压包内的 **`class-score-miniapp`**，不要选外层教程文件夹，也不要选 `cloudfunctions`。
5. 项目名称可填写“我的班级积分站”。AppID 再次填写/核对**你的真实 AppID**。
6. 后端服务如果有选项，选择“微信云开发”。导入已有源码，保留原项目内容，不用另外生成覆盖它的模板项目。
7. 导入后，左侧文件树应有 `app.js`、`app.json`、`pages`、`services`、`cloudfunctions`。
8. 在“详情/项目设置”检查：项目类型为小程序，云函数根目录为 `cloudfunctions/`。本版本配置的基础库为 3.6.6；先按项目现有配置验证，工具要求升级时再确认兼容性。

本项目主程序是原生 JavaScript/WXML/WXSS，不需要先安装 Node.js，也不需要为主项目执行 `npm install` 或“构建 npm”。两个云函数的依赖在后面选择“云端安装依赖”。

首次运行可能出现项目来源/信任提示，核对来源后由你本人决定是否允许运行。当前小程序提示“云开发尚未配置”是预期结果，下一步配置自己的环境。

**成功标志：**工具能打开正确文件树；页面可以显示待配置状态，没有因为选错目录而找不到 `app.json`。

## 05 开通你自己的云环境

1. 在开发者工具点击顶部“云开发”入口。
2. 首次使用时，按引导开通云开发，确认当前绑定的是你自己的 AppID。
3. 创建一个供本班使用的环境，名称可填写“班级积分正式环境”。环境实际 ID 由平台生成/确认，环境名称只是便于你识别。
4. 如果需要确认服务条款、实名认证、套餐或计费，按你账号当前条件完成。不要假定环境永远免费；在控制台核对额度和有效状态。
5. 打开环境详情/设置，复制 **环境 ID**，填入 `配置记录表.txt`。
6. 在工具中打开 `app.js`，将第一项占位值替换为你的实际环境 ID：

```js
const CLOUD_ENV_ID = '替换为你刚复制的真实云环境ID'
const CLASS_ID = 'YOUR_CLASS_CONFIG_DOC_ID'
```

7. 保存。云控制台环境选择器以及云函数根目录应选中这个相同环境；必要时右键 `cloudfunctions` 选择/切换环境。

两个环境即使名称相同，ID 不同也不是同一套数据。暂时不要填写朋友原来的环境 ID，也不用申请朋友环境的访问权限。

**成功标志：**你能在自己的账号下看到环境；`app.js` 中 `CLOUD_ENV_ID` 与控制台环境 ID 一字不差，`CLASS_ID` 此时仍是占位值。

## 06 建立 9 个数据库集合并设置权限

在自己的云控制台选择“数据库”，依次“新建集合”。集合名大小写严格按下表输入；它们可以理解成数据表。

| 集合名 | 保存什么 | 客户端权限目标 |
| --- | --- | --- |
| `classConfig` | 学校、班级、当前学期和管理员名单 | 用户可读，客户端不可写 |
| `terms` | 学期文档 | 用户可读，客户端不可写 |
| `groups` | 小组资料 | 用户可读，客户端不可写 |
| `students` | 学生资料 | 用户可读，客户端不可写 |
| `scoreRules` | 评分规则 | 用户可读，客户端不可写 |
| `scoreRecords` | 每一笔原始积分流水 | 用户可读，客户端不可写 |
| `settings` | 徽章等展示设置 | 用户可读，客户端不可写 |
| `counters` | 学生数字 ID 的计数器 | 客户端不可读、不可写 |
| `auditLogs` | 服务端操作审计 | 客户端不可读、不可写 |

### 怎么选择权限

1. 创建集合后打开其“权限设置/数据权限”。
2. 前七个集合选“所有用户可读，仅管理端可写”一类预设，常见标识为 `ADMINWRITE`；有些界面用词是“仅管理员可写”。
3. `counters` 和 `auditLogs` 选“仅管理端可读写”，常见标识为 `ADMINONLY`。
4. 保存每个集合的设置。若界面名称不同，按表中的权限效果判断。

这里“管理端”指控制台/云函数等服务端权限。你以后在小程序里成为管理员，也不是让客户端直接写数据库：写操作由 `score` 函数校验身份后完成。

**不要把所有集合设为任意用户可写；也不要把前七个都设成客户端不可读。**前者偏离本项目写入流程，后者会使页面读不到数据。

### 初始要填多少数据

接下来只手工建立一条 `classConfig` 班级文档和一条 `terms` 学期文档。其他七个集合先保留为空。程序新增学生时会处理学生数字 ID、小组和计数器，不需要手工创建初始总分、计数器值或示例积分。

**成功标志：**列表中有全部 9 个集合，名称正确、权限已保存。

## 07 创建你的班级，并取得 CLASS_ID

1. 进入 `classConfig` 集合，点“添加记录/添加文档”。
2. 用 JSON 编辑方式粘贴下面示例，改成你的学校、班级、年级、学期和日期。如果控制台只有字段编辑器，按示例逐项填写；`managers` 是 Array，初始为空数组。

```json
{
  "schoolName": "你的学校名称",
  "className": "七年级1班",
  "grade": "七年级",
  "termName": "2026秋季学期",
  "termStart": "2026-09-01",
  "termEnd": "2027-01-31",
  "current_term_id": "term-2026-autumn",
  "privacyMode": "full",
  "managers": []
}
```

3. 先让数据库自动生成文档 `_id`。保存后，在这条文档中复制 `_id`，记到配置表。
4. 回到 `app.js`，将第二项占位值换成刚才生成的 `_id`：

```js
const CLOUD_ENV_ID = '你自己的真实云环境ID'
const CLASS_ID = '你刚创建的classConfig文档_id'
```

5. 保存。这里的中文示意都需要换成实际字符串，不要原样粘贴。

### 字段怎么理解

| 字段 | 要填什么 |
| --- | --- |
| `schoolName`、`className`、`grade` | 你实际需要展示的学校、班级和年级 |
| `termName` | 学期展示名称 |
| `termStart`、`termEnd` | `YYYY-MM-DD` 格式日期，开始不晚于结束；示例日期按实际学期修改 |
| `current_term_id` | 你自己约定的当前学期业务 ID，下一节的 `id` 必须相同 |
| `privacyMode` | `full` 显示全名；`initial` 用于榜单首字展示 |
| `managers` | 能管理本班的真实 openid 字符串数组，暂时留 `[]` |

**CLASS_ID 是文档的 `_id`，不是班级名称、年级、AppID 或学期 ID。**不要给 `_id` 复制朋友原班级的值。

包内 `templates/classConfig.example.json` 提供同样结构。使用模板也必须修改学校、班级和日期，保存后仍需复制实际生成的 `_id`。

**成功标志：**你有一条班级文档；`app.js` 两项配置均已是真实值；`managers` 尚为空是正常的。

## 08 创建当前学期

1. 进入 `terms` 集合，添加文档。
2. 粘贴下面内容，把 `class_id` 换成第 07 节复制的真实 `CLASS_ID`：

```json
{
  "id": "term-2026-autumn",
  "class_id": "替换为你的真实CLASS_ID",
  "name": "2026秋季学期",
  "start_date": "2026-09-01",
  "end_date": "2027-01-31",
  "status": "active"
}
```

3. 学期名称和日期改成实际值，与班级配置同步。`id` 则与 `classConfig.current_term_id` 相同。
4. `_id` 如果可自定义，可以设为 `term-2026-autumn`；如果自动生成，保留自动值，并确保上面的业务 `id` 字段存在且正确。
5. 保存。使用模板 `templates/terms.example.json` 时同样必须替换 `class_id`。

### 保存前核对这三组关系

| 左边 | 必须等于右边 |
| --- | --- |
| `terms.class_id` | `app.js` 的 `CLASS_ID`，也就是班级文档的 `_id` |
| `terms.id` | 班级文档的 `current_term_id` |
| `terms` 的名称与日期 | 班级配置的对应学期名称与日期 |

`status` 用 `active`。本版本不接受给已归档/停用学期继续记分。当前学期不存在或归属班级不一致时，即使首页能打开，也可能出现 `TERM_NOT_FOUND`；不要跳过这一步。

**成功标志：**一条有效学期文档已经关联你的班级，且当前日期位于准备使用的学期范围内。

## 09 部署两个云函数

项目中的两个云函数都是必需的：

- `whoami`：确认当前微信用户的 openid，以及是否是本班管理员。
- `score`：处理学生、规则、积分和设置的管理写入，并检查权限。

### 先部署 whoami

1. 核对云开发当前环境就是你的环境；右键云函数根目录选择相同环境。
2. 左侧展开 `cloudfunctions`，右键 **`whoami` 文件夹**。
3. 选择“上传并部署：云端安装依赖”或同义选项。不要只上传 `index.js`，整个函数目录包含所需的 `package.json`。
4. 等待成功，云控制台“云函数”列表中应出现全小写 `whoami`。
5. 打开 `whoami` 的“配置/环境变量”，添加一条：

| 键 | 值 |
| --- | --- |
| `CLASS_ID` | 你第 07 节获得的班级文档 `_id`，不带外层引号 |

6. 保存；如果控制台要求发布配置、部署或切换生效版本，完成对应操作。确认当前函数用的是新配置。

环境变量是在**云端函数配置**里设置，不是修改电脑 Windows 环境变量，也不是给 `project.config.json` 增加一个同名字段。

### 再部署 score

1. 右键 **`cloudfunctions/score` 文件夹**。
2. 同样选择“上传并部署：云端安装依赖”。
3. 等待成功，控制台确认全小写 `score` 已存在。
4. 本版本 `score` 使用请求中的班级 ID 并在服务端校验，不要求再配置 `CLASS_ID` 环境变量。

两个函数的 `package.json` 都声明 `wx-server-sdk`。云端安装依赖用于避免缺少 SDK；不是对主项目做 npm 构建。运行环境先使用控制台提供的受支持 Node.js 默认选项，遇到兼容错误时按函数日志处理。

### 五个位置最后对齐一次

| 位置 | 应填写的值 |
| --- | --- |
| `project.config.json` → `appid` | 你的 AppID |
| `app.js` → `CLOUD_ENV_ID` | 你的云环境 ID，两个函数也部署到此环境 |
| `app.js` → `CLASS_ID` | 你的班级文档 `_id` |
| `whoami` 环境变量 → `CLASS_ID` | 同一个班级文档 `_id` |
| `terms.class_id` | 同一个班级文档 `_id` |

**成功标志：**自己的环境里有两个部署成功的函数，`whoami` 的环境变量已生效。

## 10 第一次运行，并把自己设为管理员

1. 在工具顶部点击“编译”。
2. 首页现在应能显示你的学校、班级；因为还没导入学生，空名单或零积分可以是正常状态。
3. 打开底部“设置”。`managers` 是空数组，所以现在显示“浏览者/当前为浏览模式”，这是正确行为。
4. 在“权限与展示”中点“查看我的 openid”，再点字符串复制。
5. 回云控制台，打开 **`classConfig` 中 `_id` 为你的 CLASS_ID 的那条文档**，把 `managers` 改成：

```json
["替换为刚复制的完整openid"]
```

6. 保存后重新编译；手机中彻底退出再进入。
7. 设置页显示“管理员”，记分页出现“记一笔”入口，表示配置生效。

openid 来自**当前小程序账号下的当前微信用户**。不能沿用朋友旧小程序的 openid，也不能填微信号、手机号、昵称或 AppID。云控制台直接“测试函数”未必有真实微信上下文，请从实际小程序里取得身份。

若另一个老师也要管理，让他先用自己的微信进入你的小程序，复制他的 openid，再追加到数组；例如：

```json
["第一位管理员的真实openid", "第二位管理员的真实openid"]
```

已是管理员的页面可能不再显示“查看我的 openid”，不需要重复配置。不要编辑代码里的 `isAdmin` 或按钮来获得管理员身份；真正写权限仍由云函数验证。

**成功标志：**你的实际使用账号被识别为管理员，拥有管理入口。

## 11 先用一名虚构学生完成真实测试

这一步验证的是你新环境里的真实读写，不是打开离线网页看看。建议在空班级里先测试，再导入正式名单。

### 新增测试学生和规则

1. “设置 → 名单管理 → ＋ 新增同学”，输入姓名“部署测试学生”，小组“一组”，点“加入名单”。
2. 看到“已加入名单”，检查名单中有该学生且右侧开关是启用。
3. “设置 → 评分规则 → ＋ 添加评分规则”，填“部署测试”、默认分值 `1`，保存。

### 加分、编辑、撤销

1. “记分 → 记一笔”，明确选中“部署测试学生”。
2. 选择加分，分值 `1`，规则“部署测试”，原因“独立部署验收”，点“确认提交”。
3. 在第二次确认框核对学生、分值、方向和原因，再确认。
4. 应看到“加分成功”；流水只新增一条，当前周和当前学期在日期范围内时，该学生相应积分为 `+1`。
5. 点击这条流水的“编辑”，分值改成 `2`，保存。应更新原记录，而不是新增另一条；总分应为 `+2`。
6. 点击“撤销”并确认。应标记已撤销，有效总分回到测试前状态。
7. 另外新增一条测试流水，再点“删除”确认；有效总分应再次恢复。删除是软删除，仍保留云端审计痕迹。

### 普通账号、手机和导出

1. 按第 14 节生成体验入口，先添加另一个微信为体验成员；不要把这个账号加进 `managers`。
2. 他扫码应能看到目标班级数据，但显示浏览者，没有记分和管理入口。
3. 你用管理员微信在手机上试记，同步检查另一台设备是否看到更新；若需重开才能更新，记录并检查监听和网络，不能直接认定实时同步已通过。
4. “统计 → 复制积分流水 CSV”能复制数据；在电脑粘贴到记事本，另存为 UTF-8 编码的 `.csv`，核对中文和列内容。撤销/软删除流水不在有效导出中，可另建一条有效测试流水检查后再撤销。
5. 完成后撤销剩余测试流水、在名单中停用“部署测试学生”。测试会留下审计痕迹，停用不会物理删除数据。

网络超时先查看流水是否已经成功写入，再决定重试。不要连续提交同一笔来“确认能不能用”。单次记分使用 1～20 的整数；加扣方向由模式决定，编辑分值可用 -20～20 的非零整数。

**成功标志：**实际学生创建、积分写入、编辑、撤销、软删除、浏览者权限和手机读取都经过验证。任何一项失败先看第 17 节，不急着提交正式审核。

## 12 换成自己的名单和四类规则

### 批量导入自己的学生

1. 用记事本整理名单，**每行一人，只放姓名和组别**，不放表头、班级标题、总人数或说明文字：

```text
示例甲 一组
示例乙 一组
示例丙 二组
```

2. “设置 → 名单管理 → 批量导入”，粘贴，核对，点“开始导入”。
3. 等待结果，再核对人数、姓名、小组和启用状态；成功才进入下一步。

当前解析规则只识别末尾的 **“一组”至“十组”**，`1组`、`第一组`、`A组` 可能被拼进姓名。自定义组名用“新增同学”逐条输入。一次文本最多 4000 字，超过时分批。

程序不按姓名去重，同名是独立学生。部分失败时先核对已成功的行，只补缺失项，不要整份再导入。不要直接把原班级名单 JSON 导入成 `students` 的一条文档。本专用包只提供虚构格式示例，不附朋友原班的真实名单。

### 添加评分规则并设置分类

1. 在设置页分别添加你要用的规则，例如“课堂表现”“体育活动”“卫生值日”“纪律提醒”。默认分值填写 -20～20 的非零整数。
2. **页面新增的规则默认全部是 `study`（学习）。**写成“体育”活动名称，不会自动切换分类；本版本页面没有分类选择器。
3. 进入云控制台 `scoreRules`，找自己班级 `class_id` 下对应 `label` 的规则文档。
4. 按下表修改它的 `category` 字段，保存；不要改文档 `_id`、业务 `id` 或 `class_id`。

| 规则示例 | category 值 | 统计维度 |
| --- | --- | --- |
| 课堂表现 | `study` | 学习 |
| 体育活动 | `sports` | 体育 |
| 卫生值日 | `labor` | 劳动 |
| 纪律提醒 | `discipline` | 纪律 |

5. 重新进入小程序，分别用四条规则试记并检查流水中的分类和统计页；验收后撤销测试流水。

修改规则分类影响后续新记录，不会自动改旧流水。记分时仍要手动核对加扣方向和分值；换规则并不保证把分值、方向一起重新设置。未配置规则时仍可填写原因记分，默认学习分类。

### 班级资料和徽章

设置页可修改学校、班级展示资料以及排名徽章。开始正式使用前清理示例文字，核对真实学生人数。当前没有学生改名/换组、完整评分规则编辑、物理删除及多班切换页面；遇到这些需求由维护者处理，不随意重写已有学生 ID。

**成功标志：**名单来自自己的班级，人数和分组正确，四类规则的真实流水归类正确。
